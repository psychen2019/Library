# Library

> 我的长期原始书库：保存完整书籍、长文本与可追溯的阅读材料，为 Second-Brain 提供需要时可以回到原文核验的 source layer。

这个仓库不是知识卡片库，也不是 Second-Brain 的镜像。它保存的是**原始材料本身**：整本书、较长的文本、课程整理稿以及未来值得长期保留的阅读来源。

这里回答的是：

> **原文到底说了什么？**

而不是：

> **我现在怎样理解它？**

后一个问题交给 `Second-Brain`。

---

## 在整个知识系统中的位置

当前几个仓库承担不同职责：

```text
ebook-treasure-chest
        ↓
发现还有哪些书值得找 / 值得读
        ↓
Library
        ↓
保存完整书籍、长文本与原始阅读材料
        ↓
真实问题 / 阅读 / 对话 / 定向检索
        ↓
Second-Brain
        ↓
Knowledge / Connections / Learning
```

另外：

- `Raven-Sprouts` 是旧知识生态与历史认知档案，保留过去已经形成的大量笔记、方法和结构；
- `Library` 是原始书库，尽量保留材料自身，而不是把每本书都重新加工成一套笔记；
- `Second-Brain` 是当前长期认知状态，只接收经过选择、比较、使用和修正后真正值得参与未来判断的内容；
- `ebook-treasure-chest` 只是 discovery catalog，用来扩大书目搜索空间，不作为正文证据。

核心原则是：**能找到一本书，不等于已经理解一本书；保存一本书，也不等于它已经进入自己的知识系统。**

---

## 这个仓库适合保存什么

适合放入这里的内容包括：

- 完整书籍的纯文本版本；
- 篇幅较长、值得保留原始上下文的资料；
- 系统性课程或讲义的完整文本；
- 未来需要反复查证、引用或重新阅读的来源材料；
- 不适合被压缩成单个 Knowledge 节点的长篇思想文本。

当前仓库已经包含《反脆弱》《问题即答案》《人生算法》《打造第二大脑》《模型思维》《思考如何超越思考》、韩炳哲作品等长文本。

---

## 不应该在这里做什么

这里不追求：

- 为每本书自动生成摘要；
- 为每一章批量创建知识卡片；
- 用标签、双链或文件数量证明“学到了更多”；
- 把 AI 的二次解释混进原始正文后再冒充原文；
- 把 Library 直接同步成 Second-Brain；
- 因为一本书被收藏，就假设其中观点已经被接受。

Library 的价值来自**保留足够丰富的原始语境**，而不是提前把一切加工干净。

---

## 推荐使用方式

Library 默认采用 **problem-driven retrieval（问题驱动检索）**。

不是：

```text
每天随机读几本
→ 批量摘要
→ 塞进知识库
```

而是：

```text
真实问题出现
    ↓
Second-Brain 现有理解不足
    ↓
确定需要什么证据 / 竞争模型 / 原始出处
    ↓
在 Library 中定向寻找相关书籍、章节或片段
    ↓
与当前 Knowledge 对照
    ↓
支持 / 冲突 / 收窄边界 / 无实质新增
    ↓
只有真正改变未来判断时才进入 Second-Brain
```

这意味着，同一本书可能长期安静地待在这里，直到某一天一个真实问题需要它。

---

## 与 Second-Brain 的关系

`Second-Brain` 可以把 Library 作为外部 Source Library 调用。

典型场景：

- 查一个理论的原始表述；
- 给现有观点寻找反例；
- 比较多个作者对同一问题的不同模型；
- 核验 Second-Brain 中某个概念是否被过度简化；
- 当一次真实对话暴露知识缺口时，回到相关书中定向补充；
- Nightly Distillation 在明确问题驱动下寻找深层来源。

Library 中的单一作者、单一本书或同一材料中的多处支持，不能自动被当作多个独立证据。

---

## 与 Raven-Sprouts 的关系

Raven-Sprouts 保存大量已经被加工过的历史笔记、旧知识结构和过去的认知痕迹，因此更适合回答：

> **过去的我曾经怎样理解这个问题？**

Library 则更适合回答：

> **原作者或原始材料到底怎样说？**

两者都可以成为 Second-Brain 的上游，但角色不同。

如果 Raven 中已有一篇二次整理，而 Library 中有原书，涉及关键事实、理论边界或争议时，应优先回到原始材料核验。

---

## 与 ebook-treasure-chest 的关系

[`jbiaojerry/ebook-treasure-chest`](https://github.com/jbiaojerry/ebook-treasure-chest) 可以作为书目发现入口：帮助发现书名、作者、主题和可能值得进一步阅读的材料。

它不等于 Library，也不承担知识证据角色。

推荐流程：

```text
发现一本书
    ↓
先检查 Library 是否已有
    ↓
已有 → 直接进入定向阅读 / 检索
没有 → 形成候选阅读
    ↓
由人决定是否获取并加入 Library
```

不要自动批量下载第三方电子书，也不要把下载页面或书目条目当作正文来源。

---

## 文件与来源原则

当前阶段保持简单：

- 尽量保留清晰、稳定、可搜索的文件名；
- 原文优先，不为了“统一格式”破坏正文；
- 如果需要补 metadata，应尽量保持最小、明确、可追溯；
- 不修改原始文本的观点来适配 Second-Brain；
- 任何二次解释应进入 Second-Brain，而不是偷偷写回原书。

Git 负责保存版本历史，因此不需要通过 `final`、`v2`、`revised` 等重复文件维持时间轴。

---

## 关于 AI

AI 可以帮助：

- 定位相关章节；
- 搜索概念和关键词；
- 比较书中不同段落；
- 找到与当前问题相关的证据与反例；
- 将真正成熟的理解提议给 Second-Brain。

但 AI 不应该把“检索到了内容”误认为“已经理解”，也不能把自动摘要数量当作学习成果。

> **Library 是记忆的外部介质，不是认知本身。**

真正的认知仍然发生在阅读、问题、比较、行动、反馈以及不断修正模型的过程中。

---

## 当前阶段

**Stage: source-library / seed**

现在最重要的不是为仓库设计复杂目录，而是先让真实阅读和真实问题告诉我们：哪些书需要更好的索引、哪些 metadata 真正有用、哪些调用方式反复出现。

如果未来出现稳定摩擦，再让结构自然长出来。

> 一本书进入 Library，只意味着我们保留了再次与它相遇的可能；只有当它改变了未来的判断，它才真正进入了 Second-Brain。
